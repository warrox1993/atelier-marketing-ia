# Audit des correctifs atelier-local du socle

Date : 07/11/2026. Issue #30. Document seulement : rien n'est modifié dans `socle/patches/` ni dans `paperclip/`.

## 1. Objet et méthode

`socle/patches/` porte 174 correctifs du socle Paperclip. 31 sont propres à l'usine (`ls socle/patches | grep -c atelier-local` donne 31) : 17 `feat-atelier-local`, 12 `fix-atelier-local`, 2 `test-atelier-local`. Chacun rend la montée de version du socle plus coûteuse. Cet audit dit, pour chacun, ce qu'il fait et où ce comportement doit vivre.

Principe : profiter de Paperclip tel qu'il est, et ne faire du sur-mesure qu'en dernier recours. Rien n'est proposé à l'éditeur. La décision est l'une de trois, dans cet ordre de préférence :

1. **Retirer (natif)** : Paperclip sait déjà le faire (réglage, fonction existante).
2. **Déplacer dans le plugin** : le SDK de `plugin-atelier` offre le crochet nécessaire.
3. **Garder avec test** : ni le natif ni le plugin ne suffisent ; un test fige le comportement (celui qui existe, ou celui qui manque).

Les deux correctifs `0078` (`fix-atelier-un-agent-ne-detache…`) et `0164` (`fix-atelier-cartes-de-la-passerelle…`) portent `fix(atelier)` sans « local » dans leur nom : ils sortent du périmètre de cet audit et du tableau.

### Où lire les preuves

- **base** : Paperclip `v2026.1023.0`, commit `1b4c803816e82b0265c8422e1a804327a7ed8c54`, sans aucun correctif. Lecture seule par `git -C paperclip show "${SHA}:<chemin>"` (le dossier `paperclip/` est ignoré par git).
- **patché** : l'arbre `paperclip/` avec les correctifs appliqués (HEAD `7077bda78d`), pour les lignes qui n'existent que grâce à eux.
- **SDK, types** : `plugin-atelier/.paperclip-sdk/paperclipai-plugin-sdk-1.0.0.tgz`, fichier `package/dist/types.d.ts`.
- **SDK, constantes** : `plugin-atelier/.paperclip-sdk/paperclipai-shared-0.3.1.tgz`, fichier `package/dist/constants.js`.

### Ce que le SDK permet et ne permet pas (constats communs)

- **Aucun crochet bloquant.** Un plugin s'abonne par `events.on(nom, gestionnaire)` (SDK types `:349` et `:358`), et le gestionnaire rend `Promise<void>` : il ne peut rien refuser. Les événements d'écriture (`issue.created`, `issue.updated`, `agent.run.started`, `agent.run.cancelled`, SDK constantes `:1304-1305` et `:1318-1321`) arrivent après coup. Une garde qui doit refuser avant l'écriture reste donc dans le moteur.
- **Réveil sans effort.** `requestWakeup` n'accepte que `reason`, `contextSource` et `idempotencyKey` (SDK types `:1193-1197`) ; le client `agents` n'a ni mise à jour de configuration ni réglage d'effort (SDK types `:1338-1356`). Nuance : la création d'une tâche accepte `assigneeAdapterOverrides.adapterConfig` (SDK types `:1165`, `IssueAssigneeAdapterOverrides` dans `paperclipai-shared-0.3.1.tgz`, `package/dist/types/issue.d.ts:105-108`), donc des réglages d'adaptateur peuvent être posés à la création. Cela ne règle pas l'effort d'un run déjà en file ni le réveil d'une tâche existante, et le SDK ne prouve pas que l'effort passe par ce champ.
- **Aucun remplacement d'écran natif prouvé.** Le SDK déclare 17 emplacements d'interface (`PLUGIN_UI_SLOT_TYPES`, SDK constantes `:1118-1136`, relus dans `paperclipai-shared-0.3.1.tgz`, `package/dist/constants.js`) : `page`, `detailTab`, `taskDetailView`, `dashboardWidget`, `sidebar`, `routeSidebar`, `sidebarPanel`, `projectSidebarItem`, `globalToolbarButton`, `appShellOverlay`, `organizationSwitcher`, `toolbarButton`, `contextMenuItem`, `commentAnnotation`, `commentContextMenuItem`, `settingsPage`, `companySettingsPage`. Aucun n'est décrit comme remplaçant un composant natif : ce sont des points d'accueil où l'on ajoute un composant. Le SDK ne documente pas le comportement de `appShellOverlay` ni d'`organizationSwitcher` ; aucun des correctifs audités ne vise ces deux emplacements.
- **Traduction native incomplète.** `i18next` est présent (base `ui/src/i18n/index.ts:6-15`) mais la langue est figée sur `DEFAULT_LOCALE = "en"` (base `ui/src/i18n/locales.ts:5`), `fr.json` ne contient que 5 clés (`app.noCompanies` et ses 3 libellés) et les écrans visés (`Sidebar.tsx`, `IssueDetail.tsx`, `Dashboard.tsx`, `ActivityCharts.tsx`) n'appellent aucun `t()`.
- **Connecteur personnalisé natif.** La galerie de connecteurs offre « Connect your own tool » (serveur MCP personnalisé) : base `ui/src/pages/apps/Browse.tsx:861-862` et `:1483-1487`. À la création de la connexion, les instructions d'agent sont posées (base `server/src/services/tool-access.ts:13211-13214`) ; « Ask first » s'applique par niveau de risque (`tool-access.ts:15377-15396`) ; le risque d'un outil se lit dans ses annotations `destructiveHint` et `readOnlyHint` (`tool-access.ts:2376` et `:2436-2437`), que la passerelle peut poser.

Constats à retenir :

- **Le natif couvre ce qui est de la donnée.** Les 7 correctifs retirables sont tous des cartes de galerie. Perte connue : les libellés et icônes français de la galerie. L'essai est dans l'issue #37. Deux correctifs voisins restent : 0003 (code serveur de la passerelle : sonde, mode démonstration, exception HTTPS) et 0004 (« Ask first » par défaut sur les écritures : le natif laisse tout autorisé), car ni le natif ni le plugin ne les remplacent.
- **Le plugin ne couvre pas ce qui doit refuser avant d'écrire.** Les gardes (0001, 0006, 0012, 0013, 0022) et les contrôles de run (0002, 0010, 0011, 0026) restent dans le moteur, faute de crochet bloquant dans le SDK.
- **Les écrans natifs ne se remplacent pas depuis un plugin.** Les 10 correctifs d'interface (0014, 0015, 0017, 0018, 0019, 0020, 0021, 0023, 0024, 0025) sont gardés ; la traduction native est présente mais la langue est figée sur l'anglais et les écrans visés n'ont pas de `t()`.
- **Un seul déplacement possible : 0027**, au prix d'un changement de comportement (deux entrées au lieu d'une). Issue #38.
- **Tests manquants** : le câblage dans `heartbeat.ts` de 0002 (inventaire des compétences) et de 0012 (escalier d'effort). Issue #39.
- **0046** ne porte plus que son test : son code est déjà natif.
